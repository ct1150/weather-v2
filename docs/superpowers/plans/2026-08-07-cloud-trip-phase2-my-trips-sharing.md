# Where Not Rain — Cloud Trip Phase 2: My Trips + Read-only Sharing

Date: 2026-08-07
Status: Complete

## Outcome

Turn `/trips` into the authenticated trip home while preserving the guest-first marketing/build/import entry points, and add safe read-only cloud sharing that can be copied into another user's independent trip.

Primary journey:

**Sign in -> My Trips -> open / archive / delete / share -> recipient opens read-only share -> copy to My Trips -> edit independently.**

## Scope delivered

1. My Trips dashboard on `/trips`, `/zh-cn/trips`, `/zh-hant/trips`.
2. Active and archived trip lists with date range, update time and cloud version.
3. Open cloud trip into the existing local-first workspace.
4. Archive / restore using optimistic version checks and stale-write `409 Conflict`.
5. Soft delete with explicit confirmation in the UI.
6. One active read-only share link per trip.
7. Share tokens generated with Web Crypto; D1 stores only SHA-256 token hashes.
8. Generating a new share link revokes the previous active link.
9. Public read-only share route in all three locales.
10. Copy shared trip to the signed-in user's independent cloud trip.
11. Multi-trip detach protection so new/imported/template trips cannot overwrite the previously open cloud trip.
12. Preview and production D1 migrations, API tests, product contract tests and smoke coverage.

## Explicitly deferred

- Collaborative editing.
- OWNER / EDITOR / VIEWER memberships.

- Realtime WebSocket / Durable Object sync.

## Security model

- A share URL is an unguessable bearer capability.
- Product-generated share URLs keep the token in the browser fragment: `.../trips/share#token=...`.
- URL fragments are read by the client and the token is sent to Trip API through `x-wnr-share-token`; the product does not put new share tokens in Pages or API request URLs.
- Raw share tokens are returned only when a share is created and are never stored in D1.
- D1 stores `SHA-256(token)` and a short non-sensitive prefix only.
- Shared trip API responses never expose owner user IDs, auth records or internal share rows.
- Shared pages are `noindex, nofollow` and API responses are no-store.
- Error logging redacts shared-trip paths so bearer tokens do not enter application error logs.
- Delete immediately makes related shares unreadable because public reads require a non-deleted trip.
- Revoke disables the current active share.
- Copy validates the stored trip document again before creating the recipient-owned trip.
- Legacy token-in-path read/copy routes remain only for backward compatibility; the current Web client uses fragment + header transport.

## Data model

### Existing `trips`

Uses existing `status IN ('active', 'archived')` and optimistic `version`.

My Trips status filtering is applied in D1 before `LIMIT`, so older archived trips are not hidden by a large active-trip set.

### New `trip_shares`

- `id` TEXT PRIMARY KEY
- `trip_id` TEXT NOT NULL
- `owner_user_id` TEXT NOT NULL
- `token_hash` TEXT NOT NULL UNIQUE
- `token_prefix` TEXT NOT NULL
- `created_at` TEXT NOT NULL
- `revoked_at` TEXT

Indexes enforce one active share per trip and efficient token-hash lookup.

## API contract

Authenticated:

- `GET /api/v1/trips?status=active|archived|all&limit=50`
- `PATCH /api/v1/trips/:tripId/status` with `{ baseVersion, status }`
- existing `GET/PATCH/DELETE /api/v1/trips/:tripId`
- `POST /api/v1/trips/:tripId/share` -> revoke old + create new raw token
- `DELETE /api/v1/trips/:tripId/share` -> revoke active link

Preferred public / mixed transport:

- `GET /api/v1/shared-trips/current` with `x-wnr-share-token` -> read-only sanitized trip
- `POST /api/v1/shared-trips/current/copy` with `x-wnr-share-token` + authenticated session -> independent copy

Backward-compatible legacy token-path routes remain supported but are not generated by the current product UI.

## Web UX

### Trips home

Authenticated users see My Trips first:

- Active / Archived tabs
- Open
- Share / regenerate share
- Revoke share
- Archive / Restore
- Delete
- New trip
- Import itinerary

Guests still see the existing hero and build/import CTAs; an account is never required to start planning.

### Share page

- Clearly marked read-only.
- Shows title, dates and day-by-day itinerary content.
- No edit controls.
- CTA: `Copy to My Trips`.
- Viewing is public; copying requires sign-in.
- English, Simplified Chinese and Traditional Chinese routes are all `noindex, nofollow`.

## Multi-trip integrity rules

- `New trip` uses an explicit new-workspace path and detaches the previously open cloud trip.
- Import detaches cloud metadata only when the imported trip is actually created.
- Template and local-share workspace sources detach the previous cloud association.
- Opening an existing My Trips item rewrites local workspace + cloud metadata to that trip.
- Local-first editing and Phase 1 conflict/offline behavior remain unchanged after opening a cloud trip.
